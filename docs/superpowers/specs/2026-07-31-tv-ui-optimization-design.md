# TV 影视中心 · 界面与播放体验优化设计

- 日期：2026-07-31
- 状态：待用户审阅
- 范围：首页信息架构、视觉规范、遥控器交互、缓冲诊断，以及分阶段的推荐 / 排行 / 题材筛选

## 1. 背景与目标

本项目是家庭电视端观影应用（FastAPI + SQLite/FTS5 + 原生 HTML/JS + HLS.js 浏览器播放，蓝牙遥控器操作）。用户反馈：

- 界面整体观感“怪”，不像成熟的电视端产品；
- 首页每个栏目是一行超长横排，远超屏幕宽度；
- 播放频繁卡顿，无法判断是视频源问题还是网络问题；
- 希望增加推荐 / 排行 / 分类能力。

本设计的目标：把主页改成电视端主流架构（焦点位 + 受限横排栏目），统一视觉与文案，提供缓冲网速诊断，并分阶段加入推荐、排行、题材筛选。每阶段独立可上线。

## 2. 现状问题（含实测数据）

### 2.1 布局
- 首页每个栏目把 20 张卡排成一行（`.card-grid.scroll-x`），实测内容宽 5180px、可视区 1808px（1920×1080），约 3 屏宽，遥控器需长时间横向滚动。
- 分类 / 历史 / 搜索页已是多行网格，无需改动（实测分类 30 卡 5 行、历史 50 卡 8 行、搜索 30 卡 8 行）。

### 2.2 数据与内容
- 首页栏目互相重复：最近更新与电影重叠 5 部、与电视剧重叠 8 部、与综艺重叠 6 部。
- 评分字段常为 0.0，前端把 0 当真值，卡片和详情页显示“⭐0”。
- 封面受源站防盗链影响经常加载失败，兜底是纯灰 SVG 色块。

### 2.3 文案与样式
- 界面中英混杂（Loading… / No data / Retry / Episodes / Play / Ep. / min）。
- CSS 中 `.section-more`、`.continue-watch` 已定义但从未渲染。
- 双强调色（金 + 红）混用，焦点框、圆角、字号层级不统一。

### 2.4 播放链路
- hls.js 通过 `cdn.jsdelivr.net/npm/hls.js@latest` 加载，国内访问不稳定且版本不可控。
- 剧集解析只在多个播放源中选“直链最多”的一个，无测速、无切换入口。
- 实测配置的“光速源”出现请求超时，源站稳定性参差。

## 3. 设计决策摘要

| 主题 | 决策 |
| --- | --- |
| 首页结构 | Hero 焦点位 + 5 个横排栏目（最近更新 / 电影 / 电视剧 / 综艺 / 动漫），每栏按当前分辨率自适应列数（1920 下 7 卡，单行满宽）+ “查看全部” |
| Hero 内容 | 继续观看优先（带进度），无历史时退化为最近更新精选大图 |
| 历史页 | 保持多行网格，卡片补“第 X 集 · 已看进度” |
| 视觉 | 深色影院感（背景 #0E0E12、卡片 #191A20），金色 #E6B91E 仅用于焦点框 / 主按钮 / 进度条 |
| 文案 | 全部中文化 |
| 封面失败 | 深色渐变 + 片名文字占位，不再显示灰块 |
| 焦点交互 | 焦点 = 唯一操作锚点；焦点移动后自动滚动跟随 |
| 键位 | 菜单键保持搜索；播放页 ↑ 键呼出诊断面板；Esc/回退键沿用现有逻辑 |
| 缓冲诊断 | 缓冲时 OSD 显示网速；诊断面板展示源域名 / 网速 / 缓冲秒数 / 码率 / 最近缓冲事件；localStorage 记录最近 50 条 |
| 新功能 | 推荐 → 排行 → 题材筛选，分五个阶段实施 |

## 4. 信息架构与交互规范

### 4.1 首页

从上到下：

1. 顶部导航（现状保留）：首页 / 电影 / 电视剧 / 综艺 / 动漫 / 历史记录 + 搜索按钮。
2. Hero 焦点位：全宽大图背景 + 左侧渐变压暗；左侧为标题、副信息（“第 X 集 · 已看 45%”）、金色“继续观看”按钮、细进度条；无历史时切换为最近更新精选。
3. 栏目区：最近更新 → 电影 → 电视剧 → 综艺 → 动漫。每栏按当前分辨率自适应列数（渲染后实测一行可放几张就显示几张，单行满宽不换行），标题右侧“查看全部 →”（最近更新栏的“查看全部”进入“最新”浏览模式，其余进入对应分类）。

操作流：

- 进入首页默认焦点在 Hero，无 Hero 时落到第一个栏目的第一张卡。
- 上下键在 Hero 与栏目行之间移动；左右键在行内移动。
- 行内到最右一张卡后再按右键 → 焦点跳到该行“查看全部”→ 再按右键或 Enter 进入对应分类页。
- Enter：Hero 续播 / 卡片进详情 / 查看全部进分类。
- 首页 Esc：焦点回到顶部导航（现状为无操作，改为回导航）。

### 4.2 分类页

- 顶部题材 Tab 行：默认“全部”，右侧为题材（阶段五实现）。
- 左右键切换 Tab，上键从卡片区回到 Tab 行；切 Tab 自动重置到第 1 页。
- 底部“上一页 / 下一页”保留；翻页后焦点回到第一张卡。

### 4.3 详情页

- 焦点顺序：播放按钮 → 剧集网格 → “猜你喜欢”行。
- 简介默认显示 3 行，按 Enter 展开 / 收起。
- Esc 返回首页的逻辑不变。

### 4.4 搜索

- 输入框 → 结果卡片 → 详情的流程保留；卡片换新视觉。
- 已修复的回退键逻辑保持：搜索框内 Backspace 删除字符，Esc 先删字、删空再关闭。

### 4.5 播放页

- 播放条按钮与左右键快进 / 快退保留；自动连播下一集保留。
- 从 Hero 续播进入时自动 seek 到记录的进度点。
- ↑ 键或播放条“ℹ”按钮开关诊断面板。

### 4.6 焦点滚动跟随（新增全局规则）

- 水平行：焦点变化后调整容器 `scrollLeft`，让焦点卡完整进入可视区。
- 垂直方向：`scrollIntoView({ block: 'nearest' })`。
- 在 `moveFocus`、`cycleNav`、`autoFocusView`、翻页后统一调用。

## 5. 数据与接口设计

### 5.1 videos 表新增列（全部可空）

| 列 | 来源 | 用途 |
| --- | --- | --- |
| `genre` TEXT | 源站 `type_name` / `vod_class` 清洗 | 题材筛选、推荐 |
| `hits` INTEGER DEFAULT 0 | `vod_hits` | 总热度 |
| `hits_week` INTEGER DEFAULT 0 | `vod_hits_week` | 热播榜主排序 |
| `douban_score` REAL | `vod_douban_score` | 高分榜主排序 |
| `remarks` TEXT | `vod_remarks` | 角标（已完结 / 更新中） |

迁移：`init_db` 检查 `PRAGMA table_info(videos)`，缺列则 `ALTER TABLE videos ADD COLUMN ...`，幂等，不删库。

索引：为 `genre`、`hits_week`、`douban_score` 建索引。

### 5.2 爬虫改动

- `_normalize_list` / `_normalize_detail` 写入上述字段。
- genre 清洗规则：`vod_class` 优先；否则从 `type_name` 去掉“片 / 剧 / 综艺 / 动漫”等尾缀，映射到统一题材集合：动作、喜剧、科幻、爱情、悬疑、犯罪、剧情、战争、恐怖、奇幻、冒险、动画、真人秀、脱口秀、选秀、纪录片等。
- 存量数据由重爬自动更新（现有 upsert 更新路径），无需手工迁移。

### 5.3 接口

- `GET /api/home`：返回 `hero` + `sections`。
  - `hero`：`{ kind: 'continue' | 'recent', video_id, title, cover, type, episode_num, episode_title, progress_seconds, total_seconds }`。
  - sections 增加“为你推荐”（有历史时）、“热播榜”（`hits_week > 0` 降序，兜底 `hits`）、“高分榜”（`douban_score > 0` 或 `rating > 0`，用非零值降序）。
- 所有行共用去重集合，任何影片一屏内只出现一次；每栏最多 7 个，数据不足就少显示；空榜不渲染。
- `GET /api/video/{id}`：返回 `related`（同 genre 或演员交集，排除自身，6~8 部）。
- `GET /api/browse`：新增可选参数 `genre`；并支持 `type=recent`（按 `updated_at` 降序，忽略分类，供“最近更新”的查看全部使用）。
- `GET /api/genres?type=movie`：返回该分类下的题材列表及数量。
- `POST /api/video/{id}/play`：新增可选参数 `start_seconds`，返回时原样带回；前端加载后 seek。

推荐逻辑（本地 SQL，无外部依赖）：取最近观看记录，按同类型 + 演员交集 / 同题材召回，按评分与更新时间排序，排除已看与自身，上限 8。

## 6. 阶段划分与交付

### 阶段一 · 缓冲诊断（先做，解决当前卡顿痛点）

- hls.js 固定版本下载到 `app/static/js/hls.min.js`，页面改本地引用；精确版本号写入文件头注释与 README。
- HLS 参数调优：`maxBufferLength=60`、`maxMaxBufferLength=300`、`backBufferLength=30`、开启 worker。
- 缓冲 OSD：`waiting` / `stalled` 时右下角显示“缓冲中… 当前网速 X MB/s”，`playing` 后消失。
- 网速计算：m3u8 用 HLS `FRAG_LOADED` 字节增量 / 时间增量滑动均值；直链文件受跨域限制时只显示缓冲提示。
- 诊断面板：↑ 键或播放条“ℹ”按钮开关；展示源域名、实时网速、缓冲提前量（秒）、清晰度 / 码率、已播 / 总时长、最近 5 次缓冲事件。
- localStorage 记录最近 50 条缓冲事件（时间、播放 URL、源名称、网速、缓冲秒数），不做后端存储。

### 阶段二 · 首页架构 + 视觉规范

- 后端：`/api/home` 增加 `hero` 与全局去重；前端：Hero、7 卡栏目、查看全部、焦点滚动跟随。
- `/api/browse` 支持 `type=recent`。
- 视觉：色彩 / 字号 / 卡片 / 焦点框 / 封面占位图 / 文案中文化全部落地。
- 详情页简介改展开式；“查看全部”与“继续观看”样式启用。

### 阶段三 · 推荐

- `/api/home` 加“为你推荐”行；`/api/video/{id}` 加 `related`；前端首页与详情页渲染。

### 阶段四 · 排行

- videos 表 5 列 + 爬虫映射 + 重爬；首页热播榜 / 高分榜两行。

### 阶段五 · 题材

- genre 清洗入库 + `/api/genres` + 分类页题材 Tab 与筛选。

## 7. 验证方式

每阶段独立提交、独立上线；每阶段结束跑一遍回归清单：搜索（含回退键删字）、详情、播放（m3u8）、历史、导航、回退保护。

- 布局：无头浏览器实测每行卡片数、页面无横向溢出、各栏无重复 id、焦点移动后滚动位置正确。
- 交互：用键盘事件模拟验证焦点流与面板开关。
- 播放：真实源播放 m3u8 验证 OSD 出现 / 消失、localStorage 日志与网速数值合理性；断外网验证 hls.js 本地加载可用。
- 视觉验收：生成前后截图给用户确认（模型无图像输入能力，以 DOM 测量保证布局数字，观感由用户验收）。

## 8. 非目标（本次不做）

- 后端诊断日志存储与上报。
- 播放源切换与多源存储（仅记录为后续方向，依赖现有 `vod_play_from` 数据）。
- 播放源测速选路与源健康度系统。
- 协同过滤 / 个性化算法。
- 独立“新片榜”（由最近更新承担）。
- 移动端 / 手机适配。

## 9. 风险与开放问题

- 源站字段可能缺失或为 0：已有“空榜不渲染、不足少显示”兜底。
- 4K 电视若 CSS 像素宽度超过 1920：卡片列数上限固定为 7，卡片宽 240px，1920 下正好满屏。
- hls.js 固定版本需与当前 Edge 版本兼容，实施第一步先本地验证。
- 不稳定源（如光速源）会影响榜单与推荐数据质量，后续可加健康度标记与自动降级。
